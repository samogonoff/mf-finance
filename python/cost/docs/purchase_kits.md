# ТЗ · Комплекты в приходе закупной продукции

Задача Б24 **668119** (Луценко Т.А., дедлайн 30.10.2026). Согласовано с
заказчиком 29.10.2026. **Реализовано 29.10.2026** (миграция 0072,
`app/purchase.py`, `CostPurchaseInvoice.vue`); механика и решения — ниже,
эксплуатационное описание — в AGENTS.md, раздел «ПФКСС по приходу (этап 2)».

## Постановка

План 8699 (закупная, «заказ готовой») содержит **комплекты**. В Лисе номер
задания выдаётся на КОМПЛЕКТ, в таможенной декларации стоят СОСТАВЛЯЮЩИЕ —
отдельные строки со своими артикулами, ценами, кодами ТН ВЭД. Нужна сборка
калькуляции комплекта из строк инвойса — по аналогии с мультипаками.

**Решения заказчика 29.10.2026:**

1. ПФКСС на составляющие комплекта **не создаётся** — только на комплект.
2. Количество комплекта вводится **вручную**.
3. Декларация комплект никак не помечает (просто строки с разными артикулами,
   ценами, ТН ВЭД) — группировку строк под комплект делает оператор в окне
   прихода.

## Что проверено по данным (29.10.2026, план 8710 — живой пример комплектов)

| Источник | Факт |
|---|---|
| портал `bm_chl_*` | комплект — ОДНА строка чек-листа (`127969-1` / `25-45509Ц-9К` «КОМПЛЕКТ ДЛЯ ДЕВОЧЕК (рубашка, галстук)», 1600 шт) со СВОИМИ заданиями `М25.12.1383/1384`. Состав структурно НЕ хранится (только в наименовании). Составляющая может быть отдельной позицией плана (рубашка `128014`, задания `М25.12.1387–1390`, 3800 шт > 1600 — продаётся и отдельно), а может не быть позицией вовсе (галстук). `calculation_json` у комплекта 8710 пуст → импорт КПСС его пропустит |
| Лиса `mat_plan`/`s_norma` | норм у закупной НЕТ ВООБЩЕ — ни у комплекта (`М25.12.1383` → 0 строк), ни у одиночки (`М25.12.1387` → 0 строк, карточки тоже). «Пустой слот» — норма для всей закупной, ценовой слот живёт в cost-базе |
| `Checks.CostHistory` | закупной нет (0 строк по обеим моделям) — как задокументировано |
| Gpartner `S_MODELI` | `KOMPLEKT=1` у статей комплекта; у комплекта СВОЯ розница/опт (25-45509Ц: 16,96 / 28,84), НДС 20, PLAN_PRICE 0 |

## Механика

```
инвойс (таможенная декларация): строки-составляющие как есть
  + комплекты инвойса: (модель, артикул, план?, задание?, количество вручную)
  + строки привязаны к комплекту (kit_id)
        │ preview — БЕЗ изменений (накладные построчно, пошлина по коду ТН ВЭД)
        ▼ apply_invoice
  строки без комплекта → ПФКСС на строку (как сейчас)
  строки комплекта → ПФКСС НЕ создают; на комплект ОДНА ПФКСС:
      ключ (kit_model, kit_articul, ПФКСС, план, задание);
      план/задание — из КПСС-основы комплекта (source_calc_sign='ПОРТАЛ'),
      если её нет — с карточки комплекта в инвойсе;
      «Основные материалы» = Σ(total_byn строк комплекта), остальные статьи 0;
      выпуск шт = количество комплекта (вручную);
      розница/уровень/НДС/бренд-менеджер — из S_MODELI комплекта
      (catalog_for_pairs + wholesale_from_retail), как у обычной закупной;
      cost_purchase_cost по ключу комплекта: source='invoice',
      snapshot с разбивкой по составляющим (аналог журнала сборок мультипака).
```

- Применённый инвойс не правится (как сейчас) — пересборки нет, stale-детект не нужен:
  себестоимость комплекта считается от строк инвойса, а не от калькуляций одиночек.
- Окно 🛒 у калькуляции комплекта работает без правок (читает `cost_purchase_cost`
  по ключу); разбивку по составляющим показывает snapshot.
- `invoice_line.manual_calc_id/purchase_cost_id` у строк комплекта — NULL,
  связь строк с калькуляцией комплекта — через комплект (kit row + snapshot).
- Строка входит максимум в один комплект (kit_id один).

## Миграция 0072

- `cost_purchase_invoice_kit`: `id`, `invoice_id` FK → invoice ON DELETE CASCADE,
  `model`, `articul`, `plan_id`, `task_number`, `qty`, `manual_calc_id`,
  `purchase_cost_id`, `created_at`.
- `cost_purchase_invoice_line` + `kit_id` FK nullable → kit ON DELETE SET NULL.
- Down: дроп обоих.

## UI (`CostPurchaseInvoice.vue`)

- Блок «Комплекты»: строки-карточки (модель/артикул с поиском среди закупных
  КПСС и справочника, план, задание — автозаполнение из найденной КПСС,
  количество вручную, Σ привязанных строк и их итог).
- В таблице строк — колонка «Комплект» (выбор из заведённых комплектов инвойса).
- Confirm применения считает комплекты отдельно: «будет создано X калькуляций
  ПФКСС (из них Y комплектов)».
- Preview раскладки — построчно без изменений; по комплекту показывать агрегат
  (Σ итогов его строк) в карточке комплекта.
