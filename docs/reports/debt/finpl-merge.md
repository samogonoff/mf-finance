# finpl-источник: слияние выручки (Table_Fin_PL) и ДЗ/КЗ (Premaster)

> Контекст: `SPEC.md`, `tasks/plan.md`. Источник `DEBT_BACKEND=finpl`.
> Реализация: `go/internal/reports/debt/repo_finpl.go` (`finplComposite`,
> `mergeFinPLPremaster`). Статус: на ревью (CHECKPOINT B).

## Проблема грануляр.

Два набора данных имеют **разную гранулярность** и валюту:

| | Гранулярность | Валюта | Поля |
|---|---|---|---|
| **Table_Fin_PL** (finpl) | Компания × Контрагент (месяц) | USD-консолидация | RevenuePeriod, RevenueLastMonth |
| **Premaster1C** (premaster) | Компания × Контрагент × Счёт × Договор | функц. валюта юрлица | ДЗ/КЗ-сальдо, договор, срок/просрочка |

## Решение (реализовано)

**Union плоских строк** — под текущую модель «плоский список + группировка на клиенте»
(UI группирует по Компания→Контрагент→Счёт→Договор→Валюта):

1. Из **Premaster** берём ДЗ/КЗ-строки; **обнуляем выручку** (её канонический
   источник теперь Table_Fin_PL) и **выкидываем чисто-выручочные** premaster-строки
   (где нет ДЗ/КЗ-сальдо) — чтобы не было двойного счёта выручки.
2. Из **Table_Fin_PL** добавляем revenue-строки как есть (USD).
3. **Closing-сальдо ДЗ/КЗ** — на конец периода `date_to` (так же, как в текущем
   mssql-отчёте; premaster считает opening/closing по проводкам).

```
result = [premaster ДЗ/КЗ-строки (revenue=0)]  ++  [finpl revenue-строки (USD)]
```

### Почему union, а не агрегат на пару
- Lossless: ни ДЗ/КЗ-детализация по счёту/договору, ни выручка не теряются.
- Не нужно «мирить» валюты (ДЗ/КЗ — функц., выручка — USD) в одной строке.
- Совпадает с тем, как отчёт устроен сейчас (несколько строк на пару).

## Известные ограничения (вход в CHECKPOINT B)

1. **Идентичность контрагента между источниками.** finpl даёт `CounterpartyName`
   (без ИНН), premaster — `PartnerINN` (+ имя из Counterparty1C). Имена не
   нормализованы («Формэль» vs «ООО «Формэль»»), поэтому revenue-строка и
   ДЗ/КЗ-строки одной пары могут сгруппироваться на клиенте как разные контрагенты.
   Возможная доработка: матчинг `CounterpartyName` → наше ЮЛ (ВГО-контрагент почти
   всегда из ГК) с проставлением PartnerINN. Пока — best-effort (имя как есть).
2. **Валюта.** Выручка показывается в USD, ДЗ/КЗ — в функц. валюте. Если нужна
   единая валюта — переключить `finPLRevenueColumn` (AmountBYN) и/или конвертацию.
3. **Контрагент с ИНН=NULL** (например Летникова) приходит из finpl как имя без ИНН —
   не роняет отчёт, отображается как есть.
