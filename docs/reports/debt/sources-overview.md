# Отчёт «Задолженность ВГО» — источники данных

Документ для согласования с аналитиком и заказчиком. Описывает **текущий боевой вариант**: откуда мы берём данные для отчёта по внутригрупповой задолженности (ВГО) на странице `/reports`, какие поля из каких источников тянем, как выводим в интерфейсе, и **что можно улучшить**.

Дата: 2026-06-29.

---

## 1. О чём отчёт

«Задолженность ВГО» — оперативный отчёт по **внутригрупповой** дебиторской (ДЗ) и кредиторской (КЗ) задолженности группы компаний «Марк Формэль» (15 юрлиц; страны РБ, РФ, КЗ, УЗ + TR/CZ/UK/CN/KG). Плюс выручка по контрагентам ГК. Доступ — роль финансового администратора.

Показываем по каждой паре «наша компания × контрагент-партнёр × счёт × договор»: сальдо ДЗ/КЗ на начало и конец периода, обороты, выручку, договор и срок/просрочку. Признак «внутригрупповая операция» — готовая метка `ICO` в источнике.

---

## 2. Откуда берём данные

Отчёт собирается из **канонического источника GLMF**, синхронизированного в локальный ClickHouse, плюс несколько справочников из учётной витрины 1С (`FinDWH`).

| Источник | Что это | Что отсюда берём |
|---|---|---|
| **GLMF** (`vGLMFAddUSD` → ClickHouse `fact_glmf`) | Каноническая полная витрина проводок ГК (свежая, ежедневная загрузка) с классификацией | Все **числа**: сальдо/обороты ДЗ/КЗ, выручка; счета до субсчёта; ИНН компании и партнёра; признак ВГО; суммы в BYN и USD |
| **Premaster1C** (субконто + `Objects`) | Бух-витрина 1С с реквизитами договоров | **Договоры**: номер, дата, название (`dim_contract` по документу) |
| **Payments.dbo.Docs** | Реестр договоров со сроками оплаты | **Отсрочка** (`Delay`) и дата оплаты по договору → расчёт просрочки |
| **Counterparty1C** | Справочник контрагентов | Человекочитаемые **имена** контрагентов |
| **CompaniesMF** | Справочник юрлиц ГК | Функциональная валюта юрлица, привязка ИНН → компания |
| **Checks.dbo.CurrencyDaily** | Курсы валют | Пересчёт сумм в BYN |

> Витрина GLMF — это агрегат бухгалтерских баз 1С группы (РФ `MF2012`, ПТИР `buh_PTIR`, КЗ `buh_kz`, УЗ `brs_buh`/`buh_uz_30`, РБ `buh_markformelle`/`formelle_denom`). Мы не ходим в каждую 1С — работаем с уже собранной витриной.

---

## 3. Какие поля из каких источников

| Поле отчёта | Источник | Как получаем |
|---|---|---|
| Страна | GLMF + справочник 15 ЮЛ | по ИНН юрлица |
| Компания / ИНН | GLMF | ИНН напрямую, имя — из справочника ЮЛ |
| Компания-партнёр / ИНН | GLMF + `Counterparty1C` | ИНН напрямую, имя — из справочника контрагентов |
| Счёт БУ и субсчёт (напр. `60.01`) | GLMF | полный счёт проводки (до субсчёта) |
| Наименование счёта | словарь счетов | по коду счёта |
| На начало: ДЗ / КЗ | GLMF | сальдо на начало периода (по корню счёта 62/60/76/1210/3310…) |
| Обороты: ДЗ / КЗ | GLMF | оборот за период |
| На конец: ДЗ / КЗ | GLMF | сальдо на конец периода |
| Выручка за период / за месяц | GLMF | проводки реализации (`GroupPL='ПРОДАЖИ'` / точные Дт/Кт по стране) |
| Договор (номер, дата, название) | Premaster1C → `Objects` | по идентификатору документа `DocID` |
| Отсрочка по договору | `Payments.Docs.Delay` | срок оплаты из карточки договора 1С |
| Дата оплаты по договору | расчёт | дата операции + отсрочка (на уровне документа) |
| Задолженность в днях | расчёт | дни от (операция + срок) до отчётной даты |
| Валюта | `CompaniesMF` | функциональная валюта юрлица (консолидация в BYN, +USD) |
| Суммы | GLMF | в BYN (нативно) и USD |

## 4. Как выводим в интерфейсе

Отчёт — плоский список строк, который интерфейс группирует на клиенте по **4 уровням** (как в ТЗ):

1. **Компания — Компания-партнёр**
2. **Счёт БУ**
3. **Договор**
4. **Документ операции** (детализация по кнопке)

Колонки строки: Субсчёт БУ и наименование, Компания, Компания-партнёр, Договор, Отсрочка, Дата оплаты, Валюта, [На начало: ДЗ/КЗ], [Обороты: ДЗ/КЗ], [На конец: ДЗ/КЗ], [Выручка: за период / за месяц], Задолженность в днях. Колонки «Счёт БУ / Наименование счёта» показываются только при группировке по счёту.

Доступны фильтры (период, юрлица, счета), сохранённые наборы фильтров и детализация по документам внутри договора (с датой оплаты и днями просрочки).

## 5. Что можно улучшить

| # | Что | Зачем / статус |
|---|---|---|
| 1 | **Выручка — подтвердить точные субсчета/корреспонденции** по странам (РБ `62.1/90.1.1`; РФ `62/90.01` + `76.09/90.01`; КЗ `1210/6010`; УЗ `4015/9010`) и сверить с прокси `GroupPL='ПРОДАЖИ'` | чтобы в выручку не попадали себестоимость/НДС; убрать риск завышения |
| 2 | **План счетов для 5 стран** (TR, CZ, UK, CN, KG): карта «счёт → тип (ДЗ/КЗ/Выручка/не нужно)» | без этого по этим юрлицам отчёт пуст |
| 3 | **Подтвердить план счетов КЗ и УЗ** (заполнен по предположению); уточнить счета `9120, 2010, 9430, 2910, 2810` в УЗ | иначе цифры по КЗ/УЗ могут быть молча неверными |
| 4 | **Срок/просрочка по кредиторке (60/76)**: нужна карта «счёт → вид субконто» (где договор, где контрагент) | сейчас срок надёжно проставляется по дебиторке (62), по кредиторке — частично |
| 5 | **Договоры по КЗ/УЗ-счетам** (1210/3310/6000): уточнить позицию субконто | повысит покрытие названий договоров |
| 6 | **Предмет/тематика договора**: подтвердить, что показываем номенклатуру/статью встречного счёта, или дать отдельный реквизит | сейчас отдельного поля «предмет» в данных нет |
| 7 | **Сверка сумм** GLMF против официального ОПУ/оборотки (1–2 ЮЛ × месяц, дельта < 1–2%) | финальная валидация перед фиксацией варианта |
| 8 | **Построчная валюта долга** (USD/EUR/CNY) | сейчас вне скоупа: транзакционной валюты долга в витрине нет, суммы — в BYN (+USD). Вернуть, если аналитик добавит валюту в источник |

> Подробности по вопросам аналитику — `docs/reports/debt/analyst-handoff.md`; требования ТЗ (колонки/формулы) — `docs/reports/debt/tz-requirements.md`.

## 6. Если данные расходятся — где искать

Карта «симптом → ответственный источник», чтобы быстро локализовать проблему.

| Что не так в отчёте | Куда смотреть в первую очередь |
|---|---|
| Неверные/нулевые **суммы ДЗ/КЗ или выручка** | GLMF (`fact_glmf`): проверить проводки по паре «компания × партнёр × счёт», корректность классификации счёта и метки `ICO=1` |
| **Выручка завышена** (попала себестоимость/НДС) | набор субсчетов реализации (см. улучшение №1) — какие проводки считаем выручкой |
| Строка **не попала в отчёт** | метка ВГО `ICO` в GLMF (если 0 — операция не считается внутригрупповой); классификация счёта (счёт вне плана → строка отбрасывается) |
| Пусто по целому **юрлицу** (TR/CZ/UK/CN/KG) | план счетов для страны не заполнен (улучшение №2) |
| Нет/неверное **имя контрагента** | `Counterparty1C` (имя) и ИНН из GLMF |
| Нет/неверное **название договора** | Premaster1C → `Objects` по `DocID`; для КЗ/УЗ — позиция субконто (улучшения №4, №5) |
| Неверная **отсрочка / дата оплаты / просрочка** | `Payments.Docs` (`Delay`, дата) — есть ли запись по договору; для кредиторки покрытие частичное |
| Странная **валюта/пересчёт** | функц. валюта `CompaniesMF` + курсы `CurrencyDaily`; построчной валюты долга в источнике нет (улучшение №8) |
| Старые/неактуальные **числа** | синхронизация GLMF → ClickHouse (инкрементальная загрузка); проверить, что данные доехали |
