# Источник факта МП — разведка на сервере (CHECKPOINT A / Q1)

> Дата: 2026-06-25. Сервер: `10.10.6.15:1433` (тот же, что FinDWH/Premaster для ВГО).
> Метод: одноразовый probe через `go-mssqldb` с кредами `MSSQL_PREMASTER_*`.
> Цель: найти реальный объект под `Источник_МП` / `ALL_view_МП` из ТЗ.

## Что говорит ТЗ (дословно)

**Приложение D «Источники данных»:**
- `Источник_МП` → **OLAP Продажи + SQL Payments.Debt** → Факт МП.
- `Источник_МП_штрафы` → **Отчёт WB / Payments** → Штрафы МП.
- `olap mf_test Продажи` → **OLAP куб mf_test.Продажи** → факт продаж (этап 1.1).
- `olap Budgeting Budget` → **OLAP куб Budgeting, срез Budget** → факт/план статей PL.

**Документ «TPL-MP формы» §4.1 «Источник_МП»:** запрос OLAP **`ALL_view_МП`**, ключи
SUMIFS `month + code_cfo + scenario + CodePL`; колонки: `Scenario, Год, Номер месяца,
CodePL, CodeCFO, Group_МП_new (Маркетплейсы_large/small), Amount_BYN, Amount_RUB,
Amount_USD` (H/I/J).

## Что реально на сервере 10.10.6.15

**Базы (sys.databases):** `FinDWH`, **`Payments`** (отдельная БД!), `Budgeting`,
**`MP`**, `PIM_MP`, `MPmultiWH`, `Audit_MPstats`, `mfportal`, `onec_data` и ~50 др.
→ **Payments — отдельная база, НЕ таблица внутри FinDWH.**

| Объект | БД | Колонки / факт | Пригодность под `Источник_МП` |
|---|---|---|---|
| `dbo.ALL_view` | **Budgeting** | Scenario, Country, Month(date), CodePL, GroupPL, CodeCFO, GroupCFO1-3, CFO, **Amount, AmountBYN** | **СЛОМАНА** на снэпшоте (`ошибки привязки` — зависит от куба/linked). Нет `Group_МП_new`, нет Amount_RUB/USD |
| `dbo.sales_and_COGG_from_FOX_marketplaces` | **FinDWH** | DocID, CodeCFO, CodePL, Date, Month, AmountWOVAT/WithVAT(+Fact+BelRub), Budget/Strat-суммы, ICO | Запрашивается, данные есть (2026-05), **но агрегат по группе 250, не по площадкам 335/336/337/954**; CodePL 1006/2006 |

## Вывод

`Источник_МП` в ТЗ — **не готовая таблица, а Power-Query-сборка** (`ALL_view_МП`)
поверх куба «Продажи» + `Payments.Debt`, с добавленным разрезом `Group_МП_new`
(площадка→large/small) и пересчётом в 3 валюты (BYN/RUB/USD). **Готового объекта
ровно с этими колонками (по площадкам × CodePL × Scenario × Group_МП_new ×
Amount_BYN/RUB/USD) на сервере нет.** `Budgeting.dbo.ALL_view` концептуально ближе
всего, но (а) сломана на снэпшоте, (б) без МП-разреза и валют.

## Что нужно от аналитика/BI (для закрытия CHECKPOINT A)

Выбрать один путь:

- **(A) BI заводит вьюху** `ALL_view_МП` (именованный объект в Budgeting или FinDWH)
  с колонками как в §4.1 (Год/Номер месяца/CodePL/CodeCFO/Group_МП_new/Amount_BYN/
  RUB/USD), починив привязки. Тогда веб: `PLANS_MP_FACT_VIEW=<db>.dbo.ALL_view_МП`,
  `PLANS_MOCK=0` — и всё. **Предпочтительно** (минимум кода у нас).
- **(B) Воспроизводим сборку у себя**: SQL поверх куба «Продажи»/`MP` + `Payments`
  + маппинг площадка→`Group_МП_new` + курсы→3 валюты. Больше кода и связности, но
  без зависимости от BI-вьюхи.

До решения — рабочий путь `PLANS_MOCK=1` (фикстуры из прототипа `Маркетплейсы_large`);
форма деградирует до пустого факта, ввод тактики не блокируется.

## Технические заметки для коннектора (когда источник определят)

- `go/internal/plans/olap_mp.go` сейчас ждёт колонки `Год / Номер месяца / CodePL /
  CodeCFO / Group_МП_new / Amount_RUB` и `FROM [<view>]`. Под реальный объект надо:
  (1) поддержать **3-частное имя** (`db.dbo.view`) — текущая `FROM [%s]` ломает точки;
  (2) выровнять имена колонок по факту (`Month` date vs `Год/Номер месяца`; валюты).
- Штрафы (CodePL=66): отдельный источник (`Источник_МП_штрафы` / Payments / отчёт WB).
- % СПП: `MP.dbo.marketplaces_spp_history` (spp_value) — отдельный поток.

# ОБНОВЛЕНИЕ 2026-07-25 — CHECKPOINT A закрыт: `Budgeting.dbo.FormToLoad*`

Аналитик дал четыре объекта. Проверены probe'ом (`cmd/mssql-probe`, живой
`10.10.6.15/Budgeting`, 2026-07-25). Путь (A)/(B) из §выше **не нужен** — вьюху
`ALL_view_МП` восстанавливать не требуется.

| Объект | Что содержит | Статус в коде |
|---|---|---|
| `Budgeting.dbo.FormToLoadFact` | ФАКТ, помесячно с 2022-01 по 2026-06 | ✅ подключён (`PLANS_MP_FACT_TABLE`) |
| `Budgeting.dbo.FormToLoadPlan` | ПЛАН/стратегия, 2026-01…2026-12 | ✅ подключён (`PLANS_MP_PLAN_TABLE`) |
| `Budgeting.dbo.FormToLoaTaktTarget` | **ТАКТИКА-таргеты**, 2025-01…2026-12 | ❌ не используется |
| `Budgeting.dbo.CodeCFO` | справочник ЦФО (страна, название, группы) | ❌ не используется (seed в коде) |

Все три FormToLoad* — одна схема: `Параметр | Страна | КодЦФО | ГруппыЦФО1 |
ГруппыЦФО2 | ЦФО | КодPL | Дата | Значение`. `Дата` — 1-е число месяца
(гранулярность месячная). Значения — BYN.

## Проверенные факты

**1. `КодPL` ↔ `Параметр` — 1:1.** Текущий запрос `SUM([Значение]) GROUP BY
(КодЦФО, КодPL)` без фильтра по `Параметр` корректен — двойного счёта нет.

| КодPL | Параметр |
|---|---|
| 1046 / 1045 | ПРОДАЖИ с НДС_СПП / ПРОДАЖИ_СПП |
| 1022 / 1006 | ПРОДАЖИ с НДС с самовыв_ / ПРОДАЖИ |
| 1106 / 1122 | ОТГРУЗКИ / ОТГРУЗКИ С НДС |
| 2006 / 6006 | СЕБЕСТОИМОСТЬ / СЕБЕСТОИМОСТЬ ПОШИВА, РАСКРОЯ, ПЕЧАТИ |
| 2106 / 6106 | СЕБЕСТОИМОСТЬ ОТГРУЗКИ / …ОТГРУЗКИ ПОШИВА |
| 5006 / 7006 / 9006 / 9106 | СЫРЬЕВАЯ / ОПТОВО-РОЗНИЧНАЯ / РОЗНИЧНАЯ МАРЖА / ОПТОВАЯ МАРЖА ОТГРУЗКИ |
| 8006 | СЕБЕСТОИМОСТЬ ПО ОТПУСКНЫМ ЦЕНАМ |

**2. Каскад СПП сходится численно.** Факт 2026, площадки large:
1046/1045 = 1.193 ≈ (1 + НДС 20%); 1022/1006 = 1.193 — то есть {1046,1045} и
{1022,1006} суть одна и та же выручка в двух ценовых базах, различие
1 − 1022/1046 = **25.6 %** = %СПП. Маппинг `mpform_spec.go` (1046 = цены менеджера
с НДС, 1006 = цена площадки без НДС) численно согласован; `deriveSPP` даёт те же
25.6 %. ⚠ Названия в источнике при этом обратные интуиции (суффикс `_СПП` стоит у
**высокой** базы) — стоит подтвердить у аналитика одним вопросом, ошибка здесь = 25 %.

**3. ⚠ `8006` в ФАКТЕ мёртв с 2023-12.** Параметр «СЕБЕСТОИМОСТЬ ПО ОТПУСКНЫМ
ЦЕНАМ» в `FormToLoadFact` есть только 2022-01…2023-12. В `FormToLoadPlan` и
`FormToLoaTaktTarget` за 2026 — есть. Следствие: строка формы «Себестоимость по
отпускным ценам» (`BShipments`, seed из факта) для 2026 фактом **не наполнится
никогда**. Вместо неё в факте с 2023 живут `2106+6106` (себестоимость отгрузки).
Решение (цена ошибки — вся строка наценки): либо seed'ить из плана/таргета, либо
переключить строку на 2106+6106, либо оставить чистым ручным вводом.

**4. Факт 2025 есть по всем площадкам** (кроме 959 «Детский мир ТЕКС») —
колонка «Факт 2025» из SPEC §9.6 реализуема сразу, отдельного источника не нужно:
тот же `MpFact(year−1, month)`.

**5. `FormToLoaTaktTarget` покрывает будущее** — до 2026-12 включительно, с 8006 и
9006; пары `1045/1046` появились только с 2026-07. Это готовый источник для
колонки «Тактика-таргет» и для пред-заполнения формы (сценарий «конструктор
12 мес 2026», SPEC §9.6).

**6. ⚠ `CodeCFO.CompanyMF` пуст полностью** (685 строк, все NULL) — ЮЛ из этого
справочника получить нельзя. Фильтр «по ЮЛ» строится на своём `dir_legal_entity`,
маппинг площадка→ЮЛ остаётся открытым вопросом к финансам.

**7. Сегмента large/small в `CodeCFO` нет.** Для всех 15 площадок:
`GroupCFO1='4.Маркетплейсы'`, `GroupCFO2='-'`, `GroupCFO3='Маркетплейсы'`,
`GroupSpecial1='Отдел маркетплейса'`. Деление 250/480 остаётся в нашем
`MarketplaceSeed()`. Полезное из справочника: `Country` (RU/KZ/UZ) и `CFO`
(наименование) — можно синхронизировать `dir_marketplace`/`dir_cfo` вместо
хардкода имён.

4. Синхронизация `dir_marketplace` из `Budgeting.dbo.CodeCFO` (страна + имя),
   сегмент — свой.
5. Подтвердить у аналитика семантику суффикса `_СПП` (п.2).
