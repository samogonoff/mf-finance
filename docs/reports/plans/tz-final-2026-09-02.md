## Часть 1. Общий принцип

Чем определяется ввод. Ориентир — форма Excel. Если значение в ней не выведено формулой, а занесено вручную, в веб-форме это поле ввода. Автоподстановку не делаем, даже когда источник в базе найден.

Источник в таком случае показываем подсказкой рядом с полем: фактическое значение и расхождение, без подстановки и без блокировки. Если позже источник появится или подтвердится — поле переключается на автоподстановку без переделки формы.

Отсюда три поля ввода: % СПП и штрафы в маркетплейсах, аренда в рознице.

## Часть 2. Решения по открытым вопросам

Факт маркетплейсов: когда считать готовым.

Данные за отчётный месяц готовятся не раньше 20-го числа текущего. Форма берёт факт за прошлый месяц. Читать вживую нельзя — в динамике данные плавают. Готовим снапшот: отдельная таблица, в которую данные питаются за период, форма читает её с отметкой «данные актуальны на …».

Штрафы маркетплейсов.

Источника нет. Поле ввода по площадке и месяцу. Подсказка — габаритные штрафы Wildberries из DWH.dbo.wb_dimensions_penalty.

Пустые строки в приёмниках.

Вычищать нельзя — историчность побьётся, старый процесс через Excel и новая форма работают параллельно и пишут в одни таблицы. Уникальный индекс не ставим. Защита от дублей — DELETE плюс INSERT в одной транзакции по логическому ключу на стороне формы.

Показатели сводки розницы.

Как в Excel, лист «результат ввода в BYN»: вся структура PL целиком, 96 строк по GroupPL + Expense + CodePL, значение AmountBYN, месяцы по столбцам. Блок в USD не делаем — в исходном файле его нет.

Владельцы статей для ЦФО маркетплейсов.

| КодPL | Статья | Владелец |
|---|---|---|
| 51 | Грузоперевозки экспорт | Логисты, ЦЗ 32 |
| 52 | Грузоперевозки развоз и перемещение | Маркетплейсы |
| 54 | Аренда помещений (стоянки) | Маркетплейсы |

По 52 и 54 доля вводится в реестре «Условия площадки», у ЦЗ 32 строки только для чтения. По 51 наоборот: владелец ЦЗ 32, в форме МП строка выводится индикатором «сумма делить на выручку», без ввода.

Условия площадки.

Вводят маркетплейсы по согласованию с финблоком. Хранение — отдельный реестр на площадку и период. Версионирование в первую версию не входит, это развитие. При расхождении введённого % СПП с фактическим — информировать, подсветить красным. Не блокировать, комментарий не требовать.

Ставка НДС на плановый период.

За предыдущий месяц. Для стратегического сценария — среднегодовая, за каждый месяц.

Аренда розницы.

Реестра договоров нет. Поле ввода по магазину и месяцу, подсказка — факт предыдущего месяца по тому же ЦФО. Этап 2 расчёта по договору не делаем.

SLA этапов.

Предупреждение. Плашка «срок истёк», подсветка строк, отправить можно как обычно. Переход не блокируется.

Читать вживую нельзя — больше двухсот процедур в DWH, FinDWH и MP перезаливают таблицы через TRUNCATE, и в динамике данные плавают. Готовим снапшот с отметкой «данные актуальны на …».

### 20. База начисления прямых затрат

**Было:** Статья = Выручка по ценам менеджера × доля_статьи.

**Верно:** Статья = Выручка по цене площадки × доля_статьи.

### 21. Формула итогового PL

**Было:** PL = Продажи по цене площадки без НДС − Себестоимость по отпускным ценам − Общие затраты − Прямые затраты + Σ Комиссия площадки.

**Верно:** PL = Продажи по цене площадки без НДС − Себестоимость по отпускным ценам − Прямые затраты.

Убраны «Общие затраты» и слагаемое + Σ Комиссия площадки. Это согласовано с правкой 20: цена площадки уже за вычетом СПП, поэтому прибавлять комиссию обратно означало бы считать её дважды. В прежней формуле слагаемое компенсировало базу по ценам менеджера, теперь компенсация не нужна.

### 22. Комиссия площадки

Проадажи по ценам менеджера без НДС – Продажи по цене площадки без НДС

### 23. Условия площадки

**Было:** владелец не определён, версионирование в первой версии, при расхождении блокировка.

**Верно:** вводят маркетплейсы по согласованию с финблоком. Реестр на площадку и период. Версионирование — развитие, в первую версию не входит. При расхождении введённого % СПП с фактическим — информировать, подсветить красным.

**Верно:** 52 и 54 — маркетплейсы, доля вводится в реестре «Условия площадки», у ЦЗ 32 строки только для чтения. 51 — логисты, ЦЗ 32; в форме МП строка выводится индикатором «сумма делить на выручку», без ввода.

### 25. Сохранившаяся связь для инверсии

**Было:** цену площадки надо выводить из долей.

**Верно:** Продажи по цене площадки = Продажи по ценам менеджера × (1 − %СПП). Проверка на данных файла: 457 380 000 × 0,69 = 315 592 200. Цену выводить из долей не нужно — MP.dbo.WB_Price_SPP_Analysis содержит цену и процент СПП одновременно.

## Часть 5. Справочник статей — расшифровка колонок

Объект Budgeting.dbo.CodePL, 423 записи. Десять колонок:

| № | Колонка | Тип | Что это |
|---|---|---|---|
| 1 | GroupPL | nvarchar | группа статей: ПРОДАЖИ, СЕБЕСТОИМОСТЬ, АРЕНДА, ВЫПЛАТЫ РАБОТНИКАМ и так далее |
| 2 | CodePL | nvarchar | код статьи |
| 3 | Expense | nvarchar | наименование статьи |
| 4 | SpecialAccess | int | флаг 0/1, тот же, что выбирается в ALL_view |

| 6 | VAT_BY | float | НДС Беларусь |
| 7 | VAT_RU | float | НДС Россия |
| 8 | VAT_KZ | float | НДС Казахстан |
| 9 | VAT_UZ | float | НДС Узбекистан |
| 10 | VAT_TR | float | НДС Турция |

### Колонки НДС

Значение — коэффициент «единица плюс ставка», не сама ставка. Общие значения:

| Колонка | Значение | Ставка |
|---|---|---|
| VAT_BY | 1,20 | 20 % |
| VAT_RU | 1,22 | 22 % |
| VAT_KZ | 1,16 | 16 % |
| VAT_UZ | 1,12 | 12 % |
| VAT_TR | 1,00 | не применяется |

Значение 1 означает, что НДС по этой статье в этой стране не начисляется.

Три примера, на которых трактовка проверена.

Статьи 50, 51 и 93 — грузоперевозки сырья, экспорта и импорта — стоят с единицами по всем странам. Это международные перевозки, они НДС не облагаются.

Статья 49 «Расходы на телефонную связь и интернет» имеет VAT_BY равный 1,25. В Беларуси услуги электросвязи облагаются по отдельной ставке 25 %.

VAT_KZ равный 1,16 совпадает с эффективной ставкой 16,00 %, посчитанной из факта по ЦФО 338, 474 и 475. VAT_UZ равный 1,12 совпадает с 12,00 % по ЦФО 339. Справочник и факт дают одно и то же.

Статьи 62 «Информационные услуги» и 63 «Таможенные услуги» имеют единицы по KZ, UZ и TR при 1,20 и 1,22 по BY и RU. Статья 68 «Приобретение имущества» — единицу только по UZ.

Как использовать в форме. Нормативную ставку брать из этих колонок по паре «статья плюс страна». Для планового периода по маркетплейсам применять эффективную ставку за предыдущий месяц, а нормативную использовать как проверку: если введённое значение выше нормативной, это ошибка.
