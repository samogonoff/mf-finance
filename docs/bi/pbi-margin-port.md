# Перенос дашбордов «Маржа выпуска» на источники проекта

Заказчик передал два файла Power BI и попросил повторить их функционал в Superset
и на фронте, но на **наших** данных — витрине `cost_calc_mv` и кэше
`cost_data_cache`, а не на прямых запросах в `gpartner`.

- `Маржа выпуска ЧНИ.pbix` — 2 страницы, 24 визуала, 59 мер, таблица `Выпуск ЧНИ`
  (52 604 строки).
- `Маржа выпускаТрикотаж.pbix` — 7 страниц, 66 визуалов, 113 мер, таблицы
  `Выпуск из Лисы` (49 949), `Поступление товара стороннего` (10 948), `Курсы`.

Оба тянут данные напрямую из MSSQL `srv-sql / gpartner` (Лиса) большим
T-SQL-запросом в Power Query. Наш кэш собран из `[Checks].[dbo].[CostHistory]` —
источник другой, но перекрытие по смыслу почти полное (см. §2).

Документ отвечает на три вопроса: что в файлах, что из этого ложится на наши
данные, и чего у нас нет физически.

маржа`, `Поступление товара стороннего`), оставшиеся от большой модели: часть из
них в этих файлах не используется ни одним визуалом.

**Про валюту.** В PBI доллар считается делением суммы BYN на *средний* курс
`curr_id = 3` за период — при разбросе курса внутри месяца это даёт ошибку. У нас
доллар лежит отдельной колонкой на каждой строке, пересчитанный по курсу на дату
расчёта (`fx_rate`), поэтому переключатель валюты у нас точнее и проще: меняем
колонку, а не делим агрегат.

**Про ФКСС.** В Лисе выпуск — это факт производства, признака калькуляции там нет.
У нас на одну модель-артикул четыре этапа (ПКПСС, КПСС, ПФКСС, ФКСС), и выпуск по
решению заказчика считается только по ФКСС. При переносе это условие обязано быть
в каждой мере выпуска, иначе объём учетверится.

## 3. Формулы: DAX → SQL

Меры выпуска переносятся напрямую. Ниже — все, что нужны визуалам обоих файлов.

| Мера PBI | SQL на `cost_calc_mv` |
|---|---|
| `Количество` / `Кол-во ед` | `sum(volume_pcs) filter (where calc_sign='ФКСС')` |
| `Стоимость выпуска` / `Опт выпуска Вал` | `sum(wholesale_price_byn * volume_pcs)` |
| `С/с выпуска` / `себ/с выпуска` | `sum(cost_byn * volume_pcs)` |
| `Маржа, руб.` / `Маржа выпуска Вал` | стоимость − себестоимость |
| `Маржинальность выпуска` / `Маржа, %` | маржа / стоимость |
| `Рентабельность %` | стоимость / себестоимость − 1 |
| `себестоимоть единицы` / `с/с выпуска штуки` | себестоимость / количество |
| `Оптовая цена` / `Средняя оптовая цена.` | стоимость / количество |
| `Сырье на выпуск, руб.` / `С/с сырья выпуска Вал` | `sum((mat_main_byn + mat_aux_byn) * volume_pcs)` |
| `Сырьевая с/с выпуска единицы` | сырьё / количество |
| `Пошив, раскрой, печать на штуку` | с/с штуки − сырьевая с/с штуки |
| `Мин на 1 шт` | `sum(sewing_minutes * volume_pcs) / количество` |
| `Минимальная оптовая цена` | с/с единицы × 1,4 |
| `Розничная цена 40/20` | рекомендуемая цена × 1,4 × 1,2 |
| `Рекомендуемая цена ОЦ` / `Рекомендуемая цена ЧНИ` | `if маржинальность < норма then с/с/(1−норма)/количество else стоимость/количество` — считается в разрезе модель-артикул + задание |
| `Маржинальность ниже таргета` | `if маржинальность < таргет then маржинальность else 0` |
| `Предыдущий месяц`, `Предыдущий год, %`, `Маржа предыдущего года`, `с/с выпуска шт предыдущего года` … | оконные функции по `production_date` со сдвигом на месяц/год |
| `Отклонение …` (их девять) | разность текущего и сдвинутого значения |
| `Темп роста к прошлому году` | текущее / прошлогоднее − 1 |
| `Отклонение по марже руб lm/ly` | маржа − маржа сдвинутого периода (данные для водопадов) |

Таргет маржинальности в PBI зашит константой `0.48` в мере «Маржинальность ниже
таргета», а «норма маржинальности» в ЧНИ — колонка на строке. У нас есть таблица
`cost_margin_targets` с целью по `level01`; при переносе тянем из неё, а не из
константы.

## 4. Что не переносится

Здесь честная граница: это не «сложно», а **нет данных**.

| Не переносится | Почему | Что нужно |
|---|---|---|
| Страница «Маржинальность закупок Товаров» целиком | покупные товары (`PRICE_UCH`, `PRICE_ZAK`, `MARZ`, `PURCH_MANAGER`) — отдельная таблица Лисы, в наш кэш не грузится | новый источник в `cost_data_cache` либо отдельная витрина |
| `Перерасход основного полотна, %`, `Отклонение по раскрою факт − план, %`, `Отклонение по стоимости основного полотна на единицу` | считаются от **фактического списания** материала (`MAT_KARTA.KOL_SPIS/KOL_OST` и раскройные карты Лисы). У нас есть норма расхода и цена материала, но факта списания нет | подтянуть раскройные карты из Лисы |
| `План. себ-ть, руб.` → страница «Отклонение сс», меры `с/с выпуска штуки Плановая`, `Отклонение факт с/с от плановой штуки` | плановой себестоимости Лисы как отдельного поля у нас нет | **заменено** (документ заказчика 27.08.2026): «норматив против факта» по ставке минуты — источник считает вторую себестоимость по фактической стоимости минуты с 01.01.2026, она загружена в кэш (миграция 0042) и вынесена отдельным листом. Подробно и про годность факта — `metrics.md` |
| `Печать (вышивка), мин.` | минут декора в кэше нет (есть только пошив и раскрой) | добавить колонку в кэш, если она есть в источнике |
| `Осн. материалы, кг` | веса нет | то же |
| Меры таблицы `KPI оптовая маржа` (отгрузки, скидки, уценки, чистые продажи, оптовая маржинальность) | это продажи и отгрузки, а не выпуск — другой контур данных | к разделу «Себестоимость» отношения не имеет |

Отдельно: у 36% калькуляций нет `volume_pcs`. Всё, что умножается на выпуск,
по ним не считается — как и в PBI, где такие задания просто не попадают в выборку.

## 5. Предлагаемый план

Порядок от общего к частному; каждый пункт даёт работающий результат.

1. **Меры выпуска в API и в датасете Superset** — §3 целиком, включая
   переключатель валюты и сдвиги на месяц/год. Это фундамент обеих страниц.
2. **Лист «Маржа выпуска»** (сводный лист ЧНИ и Трикотажа — они отличаются только
   фильтром по ассортименту): KPI-плитки с нормой, динамика маржи с темпом роста,
   динамика маржинальности, столбчатые по бренд-менеджерам, донат по level01,
   матрица с проваливанием до задания.
3. **Лист «Динамика себестоимости»**: KPI с/с штуки (факт / пр. месяц / пр. год),
   прирост, матрица с/с и сырьевой с/с с отклонениями.
4. **Водопады отклонений** маржи к прошлому месяцу и к прошлому году.
5. **Норматив против факта** — вместо «плановой себестоимости». Заказчик
   уточнил (документ «Фактическая и нормативная маржа выпуска», 27.08.2026):
   нужны фактическая и нормативная стоимость минуты; факт уже считается
   источником с 01.01.2026 — загружен в кэш (миграция 0042), дашборды ведутся по
   факту с явным покрытием, отклонение факт/норматив — отдельным листом.

Пункты 1–4 перенесены один в один; пункт 5 — по уточнению заказчика. Статус —
`metrics.md`, разделы «Маржа выпуска» и «Нормативная и фактическая
себестоимость».
